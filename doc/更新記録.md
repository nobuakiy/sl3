# 更新記録

## 2026-08-19: doc/BNF.md を実装に合わせて修正

`doc/BNF.md` と `src/parser.py` / `src/lexer.py` を突き合わせ、記述が実装と食い違っていた
箇所をドキュメント側で修正した(実装は変更していない)。

- **メソッド呼び出しの括弧は必須**: BNFは `obj.method`(括弧なし)も受理されると
  書いていたが、実装は括弧なしだとビットアクセス構文として解釈しようとしてエラーになる。
  `<method_arguments>?` を `<method_arguments>` に変更し、補足文も修正。
- **`PORT[addr].bit` の扱いを明記**: `<bit_access>` は識別子限定の定義だったが、
  実装は `PORT[...]` にも直接ビットアクセスできる特別扱いがある。
  `<port_access>` に `<port_bit_suffix>?` を追加して反映(`MEM[...]` には同様の構文がないことも明記)。
- **`for ... in ...` の対象は識別子限定**: BNFは `in` の後ろを `<expression>` としていたが、
  実装は結果を無条件に変数アクセスとして扱うため、配列変数の識別子以外を渡すと
  構文エラーではなく未処理の例外になる。`<expression>` を `<identifier>` に変更し、
  補足として制限と失敗時の挙動を追記。
- **未対応演算子の注記を精緻化**: `&&`/`||`/`!`/`<<`/`>>` は字句解析の時点で
  トークンとして存在しないが、`|`/`^` は字句解析ではトークン化されるだけで
  構文解析側が使っていない、という違いを分けて記載。

## 2026-08-18: Pylance/pyright型エラーの解消 (codegen_z80.py, codegen_8086.py ほか)

`codegen_z80.py` で大量に出ていたPylanceエラーを解消し、同じ原因で発生していた
`codegen_8086.py`・`parser.py`・`symbol_table.py`・`lexer.py` のエラーもあわせて解消した。
pyright実行で確認した`src/`全体のエラー数は 148件 → 0件。

### 共通の原因と直し方

1. **`self.symbol_table` が `ScopedSymbolTable | None` 型なのに未チェックで使っていた**
   - 各メソッドの先頭に `assert self.symbol_table is not None` を追加。
   - `generate()` で必ずセットされてから使われる実装上の前提を、型情報として明示した。

2. **`symbol_table.lookup()` が返す `Symbol | None` を、`VariableSymbol` 固有の属性
   (`.scope` / `.offset` / `.is_array` / `.is_const` / `.const_value`) へ
   チェックなしでアクセスしていた**
   - `if not symbol or not isinstance(symbol, VariableSymbol): ...エラー処理...` という
     ガードを追加。
   - これは型チェックのためだけでなく、**存在しない変数を参照すると
     `AttributeError` で落ちていた実際のバグ**でもあった箇所が複数あった
     (例: `visit_ArrayAccess`, `visit_BitAccess`, `visit_ForInStatement` など)。

3. **`_error()` の戻り値型が `None` のままだった**
   - `-> NoReturn` に変更。これにより `if ...: self._error(...)` の後続コードで
     `symbol` が `VariableSymbol` かつ非`None`であると型推論されるようになり、
     2.のガードを一箇所書くだけで以降の同じ変数の使用箇所すべてのエラーが解消した。

4. **汎用 `AST` 型のノードから、実際は `Number` / `VarAccess` / `StringLiteral` だと
   分かっている属性(`.value` など)に直接アクセスしていた**
   - 「簡単のため○○と仮定する」という既存コメントの通りの前提を
     `cast(Number, node.expr)` のように明示するかたちで解消。

5. **`_get_start_line` などで `hasattr()` + 直接属性アクセスをしていた**
   - `getattr(node, 'token', None)` を使う書き方に変更。pyrightは動的な
     `getattr` 呼び出しには属性存在チェックをかけないため、意図通りの
     ダックタイピングのまま型エラーが消える。

### 型エラーの指摘で見つかった実際のバグ

型エラーを追う過程で、単なる注釈不足ではなく実行時に確実にクラッシュする
不具合も見つかったため、あわせて修正した。

- **`codegen_8086.py`: `visit_FuncCall` が存在しないメソッド `self._error()` を
  呼んでいた。** `print`/`printf` の引数チェックに失敗する経路を通ると
  `AttributeError` になっていた。→ `codegen_z80.py` と同じ `_error()` メソッドを追加。
- **`parser.py`: `parse_variable_declaration` が存在しない属性
  `self.symbol_table.constants` を参照していた。** `const x = OTHER_CONST;` のように
  他のconst変数を初期値に使うと必ず落ちていた。→ 既存の `lookup()` + `is_const`
  パターンに置き換えて修正。
- **`codegen_z80.py` / `codegen_8086.py`: 複数の `visit_*` メソッドで、
  未定義の変数・配列・for-inのループ対象を参照した際にNoneチェックがなく、
  エラーメッセージなしでクラッシュしていた。** → 他の箇所と同様のエラーチェックを追加。
